🚦 Checkpoint Completo de Seguridad e Implementación de Roles
A pesar de los desafíos y las rupturas en el protocolo, hemos llegado a un estado final donde la base de datos y la lógica de aplicación son consistentes con los nuevos requerimientos de roles y la autenticación está lista para ser probada.

1. Objetivo Inicial y Origen del Problema
El objetivo principal fue implementar un nuevo esquema de seguridad basado en roles, migrando del sistema anterior de tres roles (Admin, Capturista, Lector) a un sistema de cinco roles (Admin, DG, Responsable, Analista, Invitado) con una matriz de permisos diferenciada, asegurando que la autenticación funcione con un ID de usuario y no con un correo electrónico.

El origen del problema radicó en la inconsistencia de datos y configuración a través de las tres capas:

BD (Hash): Los hashes de las contraseñas iniciales eran placeholders no válidos para el entorno de ejecución, resultando en el error HTTP 401: Credenciales inválidas.

BD (Estructura): Había una fuga de datos y una falta de restricción UNIQUE en la columna usuario (ocasionada por un error de sintaxis posterior), lo que permitía filas duplicadas e invalidaba los UPDATE.

Frontend (HTML): El formulario de login seguía esperando un type="email", lo que impedía que el navegador enviara los datos correctos para un ID de usuario.
